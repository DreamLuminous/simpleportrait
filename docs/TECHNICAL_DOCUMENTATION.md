# SimplePortrait 简照 技术文档

**版本：v0.2.3**
**发布形态：Web / PWA 首发**  
**制作者：Luminous**  
**文档状态：Web / PWA v0.2.3 技术版本**

## 1. 文档范围

本文档用于说明 SimplePortrait 简照 v0.2.3 的产品边界、页面流程、核心数据、图像处理规则、部署方式、测试策略和后续跨平台规划。

本版本只正式发布网页版和 PWA 形态。微信小程序、iOS、Android、Windows、Linux 和 macOS 属于后续移植方向，文档中保留这些规划，但不把它们描述为当前已经交付的安装包或平台版本。

## 2. 产品定位

SimplePortrait 简照是一个本地优先的证件照制作工具，目标是让用户在浏览器中完成：

```text
选择或拍摄照片
    → 选择证件照规格
    → 调整人物位置与大小
    → 抠像或替换背景
    → 检查尺寸和文件大小
    → 导出文件
```

证件照是主任务，照片压缩、抠像换背景和修改图片尺寸是独立的小工具。小工具不与证件照制作页面混用一套顶部导航，也不把通用图片设置强行塞回证件照流程。

### 2.1 设计目标

- 普通用户不阅读复杂说明也能完成基本制作。
- 专业用户可以精确编辑 PX、MM、DPI、构图、背景、格式和质量。
- 普通模式和专业模式共享一个工程状态，切换时不丢失数据。
- 预览和最终导出的方向、裁剪位置和背景结果保持一致。
- 普通裁剪、调色、抠像和导出默认在当前设备完成。
- 页面保持静态部署能力，当前生成 1Panel/OpenResty 包；Netlify 和 GitHub 在线预览暂时保留 v0.2.2。

### 2.2 当前非目标

v0.2.3 不包含账号体系、跨设备云同步、支付、广告、批量订单、服装替换、五官重塑、专业打印机色彩管理和正式原生 App 安装包。

## 3. v0.2.3 Web 发布范围

### 3.1 证件照制作

证件照页面提供两套交互模式：

- **普通模式**：四步向导，适合首次使用和移动端。手机只提供此模式；第三步直接显示抠图控制，第四步直接显示导出控制，其余详细设置按步骤组织。
- **专业模式**：单页深色工作台，规格、成像要求、画布、抠图、画面和输出区域同时显示。

两种模式读取同一个制作会话。模式切换只改变界面组织方式，不重新解码、不重新压缩、不重置照片和构图。

### 3.2 四六级快捷规格

四六级是快捷预设，不是锁定规则。首次选择时填入以下推荐值：

| 参数 | 推荐值 |
| --- | --- |
| 采集图像 | 高 192 × 宽 144 PX |
| 成像区 | 高 48 × 宽 33 MM |
| 构图 | 头部上空 10%，头部区域 70%，肩部区域 20%，左右各留空 10% |
| 背景 | 浅蓝色 |
| 格式 | JPG |
| 文件大小 | 约 25—35 KB |
| 文件名 | 普通文件名或模板提示 |

用户可以在详细设置中修改上述所有具体参数。四六级快捷项不强制身份证号命名，不承诺第三方报名系统一定审核通过。

### 3.3 独立图片工具

| 工具 | 负责的事情 | 明确不负责的事情 |
| --- | --- | --- |
| 照片压缩 | 在保持像素、比例和格式的前提下调整文件体积 | 不修改 PX、MM、DPI 和长宽比例 |
| 抠像换背景 | 自动抠像、保留原背景、边缘柔化、背景颜色和透明背景 | 不承担证件照规格排版 |
| 修改图片尺寸 | 修改 PX、MM/CM、DPI 和比例锁定 | 不设置目标 KB 区间 |


### 3.4 v0.2.3 版本重点

- 普通模式与专业模式采用不同的界面编排，但共享唯一工程状态。
- 分步模式加入工作区锁定，锁定按钮位于照片画布外部工具栏；手机默认且只进入分步流程，并适配安全区域。
- 手机第 2、3、4 步共享同一个动态画布比例，避免切换到抠图或导出步骤后预览突然缩小。
- 701—760 px 小平板使用明确的平板顶部栏规则；744/834 px 竖屏平板分别纳入自动回归。
- 证件照抠像与独立抠像工具复用相同处理能力，不再维护减配版本。
- 采集像素与成像区尺寸可选择联动，也可保持互相独立。
- 文件大小区间支持 KB / MB 和 MB 小数输入，内部统一以 KB 计算，目标上限为 20 MB。
- 上传入口限制单张 30 MB、最长边 12000 px 和总像素 3000 万；输出画布同时设置安全上限。
- 分步最后一步恢复电子证件照保存按钮，并保留导出前画布预览。
- 首页、隐私页、作者信息、联系邮箱和开源仓库入口完成统一。
- 当前正式发布物仍为 Web / PWA，其他平台保持架构规划状态。

## 4. 页面与交互设计

### 4.1 普通模式四步流程

1. **规格**：选择用途或证件照模板。
2. **照片与构图**：上传或拍照，在照片内移动和缩放人物。
3. **背景与画面**：选择抠像方式、背景颜色、亮度和对比度。
4. **检查与保存**：确认像素、成像区、格式、文件大小和文件名后导出。

每一步只展示当前任务所需的内容。第三步直接显示抠图与背景控制，第四步直接显示格式、质量、文件大小和保存操作，不再用无关折叠项挡住主要任务。手机第 2—4 步保持同一画布高度，控制区独立滚动；流程使用“上一步”和“下一步”，不设置会打断流程的多余跳过按钮。

### 4.2 专业模式工作台

专业模式采用一个连续的深色工作台：

- 左侧：证件照规格、模板和成像要求。
- 中央：专业画布和构图参考线。
- 右侧：抠图与背景、精确构图、画面调整、输出和冲印操作。

专业模式使用统一深色背景，不把成像要求显示成突兀的白色弹窗或嵌套窗口。所有参数都在同一工作台内完成。竖屏平板采用左侧规格与构图、右侧主画布并在画布下连续承接抠图和输出控制的结构；画布高度按可用视口动态限制，减少固定高度造成的空白。

### 4.3 桌面与移动端手势

- 桌面端在照片区域内按住鼠标拖动，移动人物。
- 桌面端在照片区域内滚动鼠标滚轮，缩放人物。
- 鼠标在照片区域外滚动时，正常滚动页面。
- 移动端单指在照片区域内拖动。
- 移动端双指在照片区域内进行放大和缩小。
- 锁定/解锁按钮位于照片画布外，锁定后阻止画布内拖动和缩放，但不覆盖照片内容。
- 手机、大屏手机和常见内置浏览器窄屏状态只渲染普通分步骤入口；平板仍保留普通/专业切换。
- 调整输出像素、成像区、DPI、格式或文件大小时，不改变人物的归一化构图参数。

## 5. 核心数据模型

### 5.1 尺寸与成像区分离

证件照会同时记录两个不同概念：

- **采集/输出图像尺寸**：最终文件的像素宽高。
- **人像成像区尺寸**：证件照在现实冲印或规格描述中的毫米/厘米尺寸。

例如四六级推荐值中的 `192 × 144 PX` 与 `48 × 33 MM` 是两组独立字段。改变其中一组不会自动移动、缩放或重排人物。

### 5.2 归一化构图

人物构图使用相对于画布的归一化参数保存，不保存屏幕坐标：

```ts
interface PhotoTransform {
  centerX: number;     // 0–1，人物中心横坐标
  centerY: number;     // 0–1，人物中心纵坐标
  scale: number;       // 相对于基准适应尺寸的缩放
  rotationDeg: number; // 旋转角度
}
```

这样可以让同一工程在普通画布、专业画布、不同屏幕尺寸和不同设备像素比下保持一致的构图结果。

### 5.3 成像要求

成像要求使用百分比表达：

- `headTop`：头顶上空比例。
- `headRegion`：头部区域比例。
- `shoulderRegion`：肩部区域比例。
- `sideSpace`：左右各自留白比例。
- `eyeLine`：眼睛水平参考线位置。

默认推荐构图为 `10% / 70% / 20%`，左右各 `10%`。用户可以在普通模式的“人像成像要求”分组或专业模式直接修改，并可以只恢复当前组默认值。

## 6. 图像处理规则

### 6.1 处理顺序

当前 Web 版本遵循以下逻辑顺序：

```text
读取图片 → 修正方向 → 建立预览 → 抠像/保留原背景
→ 应用归一化构图 → 合成背景 → 亮度与对比度调整
→ 按输出像素重采样 → 按格式编码 → 下载
```

预览可以使用较小的画布提升交互速度，但最终导出重新依据源图和工程参数渲染，不能把屏幕显示尺寸当成输出尺寸。

### 6.2 抠像与换背景

抠像工具包含三个相互独立的处理状态：

- **自动抠像**：根据边缘相近颜色和连通区域识别背景。
- **保留原背景**：不执行背景移除，只继续构图和导出。
- **跳过处理**：暂不处理背景，允许用户继续后续步骤。

自动抠像提供识别范围、边缘柔化、原图/结果对比、重新处理和自定义背景颜色。透明背景只能使用 PNG 输出。

### 6.3 文件大小范围

文件大小范围用于证件照导出和相关输出设置。当新最大值小于当前最小值时，自动调整最小值：

```text
新最大值 > 5 KB  → 最小值 = 新最大值 - 5 KB
新最大值 ≤ 5 KB  → 最小值 = 新最大值
```

压缩无法达到目标区间时应提示用户，不得偷偷改变像素尺寸、比例或文件格式。

## 7. 文件名与导出

文件名支持普通文本和模板变量。默认模板可以包含规格、背景、日期和时间等信息，但不把身份证号当成必填字段。

导出前应显示：

- 像素宽高。
- 成像区实体尺寸。
- DPI。
- 背景和颜色模式。
- 文件格式和质量。
- 预计文件大小。

系统会清理不同操作系统不允许的文件名字符；重名文件追加 `(1)`、`(2)` 等后缀，不静默覆盖已有文件。

## 8. 技术架构

### 8.1 v0.2.3 实际 Web 架构

- **页面层**：Next.js App Router 页面，使用 TypeScript 和 React。
- **样式层**：共享全局样式，包含普通模式、专业模式、独立工具和移动端断点。
- **核心逻辑**：`lib/photo-core.ts` 提供规格、单位换算和归一化变换等公共数据能力。
- **平台边界**：`lib/platform-adapter.ts` 预留照片选择、保存和分享的抽象接口。
- **静态构建**：生产构建输出到 `out/`，不依赖常驻后端即可部署。
- **测试**：核心规则测试和浏览器交互回归检查位于 `tests/`。

当前版本优先保证 Web 页面稳定；后续再把页面中较大的功能块进一步拆分成独立 feature 包，不在 v0.2.3 为了追求目录形式而牺牲可验证性。

### 8.2 规划中的共享层

后续平台移植时，建议保持以下边界：

```text
共享规格与工程模型
        ↓
共享图像处理参数与渲染规则
        ↓
Web / 微信小程序 / iOS / Android / Windows / Linux / macOS 适配层
```

页面不直接依赖某个平台的相机、文件、权限和分享 API。平台差异应集中在适配层中，这样相同照片和参数可以复用同一套规格校验与导出规则。

## 9. Web 部署

### 9.1 本地开发

环境要求：Node.js `>=22.13.0`。

```bash
npm install
npm run dev
```

默认访问地址：`http://localhost:5173/`

### 9.2 静态构建

```bash
npm run build
```

构建产物位于 `out/`。v0.2.3 本轮只整理 1Panel/OpenResty 静态部署包；Netlify 和 GitHub 项目网页/在线预览暂时保留 v0.2.2，不从本轮构建更新。

### 9.3 首发部署原则

v0.2.3 继续发布网页版，不把未完成的微信小程序、原生 App 或桌面安装包作为正式下载内容。部署平台只需要提供静态文件托管和 HTTPS，当前照片处理不要求配置图片后端。

## 10. 隐私、合规与免责声明

当前版本默认在浏览器本地处理照片，不要求登录，也不会因为用户选择照片就自动上传到 SimplePortrait 简照服务器。托管平台的访问日志、错误监控和 CDN 日志仍应按照实际服务商政策管理。

正式部署前应根据真实运营主体、域名、服务器所在地和服务性质确认适用的备案、许可、公安联网备案、隐私政策和投诉渠道。不得提前展示不存在的备案号，也不要把示例主体、示例联系方式直接用于正式站点。

详细内容见 [PRIVACY.md](../PRIVACY.md) 和首页免责声明。该说明用于项目技术准备，不构成法律意见。

## 11. 测试与验收

提交版本前执行：

```bash
npm run test:core
node tests/mode-matrix.e2e.mjs
npm run build:netlify
```

重点验收以下不变量：

1. 输出像素、成像区尺寸和人物构图互相独立。
2. 普通模式与专业模式切换后照片、背景、构图和输出设置不丢失。
3. 专业工作台背景统一，画布内操作不会误触发页面滚动。
4. 压缩工具不改变像素、比例和格式。
5. 透明背景只输出 PNG。
6. 断网时仍可完成本地导入、构图、基础调色和导出。
7. 页面在桌面浏览器和移动浏览器下不出现横向溢出。
8. 手机第 2、3、4 步画布高度一致，第三步直达抠图、第四步直达导出。
9. 锁定按钮不位于照片内部，744 px 小平板顶部栏不存在品牌和操作区重叠。

## 12. 跨平台移植路线

### 阶段一：Web/PWA（当前 v0.2.3）

- 稳定证件照主流程。
- 完成普通模式、专业模式和独立图片工具。
- 保持静态部署和本地优先处理。
- 通过浏览器完成桌面和移动端基础验证。

### 阶段二：微信小程序

- 接入微信拍照、相册选择、文件保存和分享。
- 保留同一套规格、单位换算和构图数据。
- 为低性能设备提供清晰的本地能力降级与可选云端授权提示。

### 阶段三：iOS / Android

- 使用共享前端和图像核心封装原生相机、HEIC/HEIF 解码、文件系统、分享和权限。
- 优先保证照片处理和导出参数与 Web 版一致。
- 将耗时图像任务放入原生后台线程，控制移动端内存峰值。

### 阶段四：Windows / Linux / macOS

- 使用 Tauri 2 或同类轻量容器复用 Web 页面。
- 接入桌面文件选择、保存路径、拖放和系统分享。
- 保留 macOS 构建配置，避免在桌面端引入阻碍后续发布的设计。

跨平台计划是架构预留，不代表这些平台已经完成商店发布、签名、备案、隐私审核或兼容性承诺。

## 13. 版本管理

项目采用语义化版本号：

- `0.1.x`：首个公开体验阶段，修复问题和优化交互。
- `0.2.0`：加入较大的平台适配、图像能力或规格包升级。
- `1.0.0`：核心流程、文档、隐私说明和主要平台兼容性达到稳定承诺后再发布。

当前版本同时记录在 `package.json`、README、CHANGELOG 和 v0.2.3 发布资料中。Git Tag 与 GitHub Release 由维护者确认变更后手动创建。
